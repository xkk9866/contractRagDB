# Knowledge-Based Systems (KBS) 投稿指南

> 基于 10 篇近三年发表于 KBS 的论文全文分析(2024–2026,均有 arXiv 全文,存于
> `paper/KBS_refs/`),覆盖 LLM 可靠性测试、RAG-VQA、LLM 信息检索系统、本体填充、
> 低资源 OpenQA、LLM+知识库综述、医学 LLM 综述、知识图谱意图预测、短语挖掘、
> 题目分类等与本项目相邻的方向。目标:提炼 KBS 论文"能够录用"的根本表达方法,
> 便于后期复刻。

## 1. KBS 的期刊气质:它究竟要什么

**一句话:KBS 要的是"以知识为中心的、能落地的、验证充分的 AI 系统方法",
而不是纯理论、纯基准刷分或纯工程报告。**

对比顶会/数据库期刊,KBS 审稿人的隐含评分表:

1. **知识视角(必须)**:方法必须能被讲成"如何获取/表示/校准/验证/利用知识"。
   十篇样本无一例外:LGMT 把测试讲成"逻辑知识蕴含的不变式";UniRVQA 把
   检索-生成讲成"参数知识 vs 外部知识的协同校准";KGFiller 把 LLM 讲成
   "知识 oracle"。**复刻要点:标题、摘要、引言、结论四处都要出现 knowledge
   的叙事框架,把技术组件映射为知识操作。**
2. **动机来自真实痛点,而非 leaderboard**:银行监管、临床、低资源语言、
   工业界数据分析——每篇都有一个"部署前必须解决"的可信性/成本/可靠性问题。
3. **方法系统化、模块化**:KBS 喜欢"框架"(framework)。方法章一定是
   一个带总览图的多组件框架,每个组件一个小节,配算法伪代码。
4. **实验极其充分但不追求 SOTA 唯一性**:RQ 驱动、多数据集、多模型、消融、
   案例分析、错误分析、资源开销分析。审稿人更在意"验证是否闭环"而非
   "是否击败所有 SOTA"。
5. **诚实的局限性讨论**:LGMT 有 "Threats to Validity",KGFiller 甚至用了
   SWOT 分析。KBS 文化上奖励自我批评。

## 2. 故事脉络(narrative arc)的标准模板

十篇论文的引言几乎共享同一个五段式结构,可直接复刻:

```
第1段 [大背景+应用价值]  LLM/KG/RAG 已被广泛集成到 X、Y、Z 应用……
                        引 4-8 篇文献堆场景。落点:某性质"是部署的前提"。
第2段 [现状+根本缺陷]    However, 现有主流范式是 P。P 内在地面临问题 Q1
                        (代价/不可扩展)、Q2(不可信/污染)、Q3(掩盖真实缺陷)。
                        用强逻辑词链:inherently / fundamentally / severely。
第3段 [已有补救+仍然不足] 为此,近期工作引入了 R。R 缓解了 Q1,但 R 目前
                        依赖 S(浅层/词法/启发式),导致新问题 T。
第4段 [我们的方案+关键洞察] To overcome/address these limitations, we propose
                        NAME,一个 XXX 框架。The key novelty/insight lies in
                        以某种"更基本的知识结构"取代 S(词法→逻辑;
                        启发式→统计保证)。两三句解释为什么这从根上解决 T。
第5段 [贡献列表]         To the best of our knowledge, this is among the first...
                        The main contributions are summarized as follows:
                        • 提出框架(1条) • 设计具体机制(1-2条)
                        • 理论/形式化分析(1条) • 大规模实验+发现(1-2条)
```

**关键修辞规律:**
- 每段都以转折词开启矛盾:However / Despite its promise / Unfortunately。
- 缺陷描述用"疾病诊断"式语言:suffer from, be susceptible to, mask,
  create a false illusion of, incur unsustainable cost。
- 方案描述用"提升维度"式语言:elevates X from A-level to B-level,
  moves evaluation beyond ... toward ..., shifts the focus from ... to ...。
- 贡献条目动词固定:propose / design / provide a formal analysis /
  construct / empirically show。

## 3. 结构骨架(照抄即可)

标准 KBS 方法论文 8 节结构(样本 1、2、9、10 的最大公约数):

```
1. Introduction
2. Related Work(或 Preliminaries + Related Work;2-4 小节,每小节末句
   必须回扣 "与之不同,我们……" 的差异化定位)
3. Preliminaries / Problem Formulation(符号、任务形式化、动机示例)
4. Methodology
   4.1 Framework Overview(总览图 + 一段流程走读)
   4.2-4.5 每组件一节;关键组件配 Algorithm 伪代码与复杂度/正确性分析
5. Experimental Setup
   5.1 Research Questions(明确列 RQ1-RQ5)
   5.2 Datasets  5.3 Baselines/Models  5.4 Metrics  5.5 Implementation Details
6. Experimental Results and Analysis
   6.x 一小节回答一个 RQ,标题直接写 "Answer to RQ1: ..." 或
   "Results of ... (RQ1)";每小节末尾放一个 "Answer/Finding" 加粗结论框
7. Discussion
   7.1 Why ...(机理解释) 7.2 Implications  7.3 Limitations and Future
   Directions  7.4 Threats to Validity(可选但加分)
8. Conclusion (and Future Work)
+ CRediT authorship statement / Data availability / Acknowledgments
+ Appendix(证明、扩展实验)
```

要点:
- **Related Work 放前面(第2节)**是 KBS 主流,与 VLDB 放最后不同。
- **RQ 驱动实验**是最显著的 KBS 风格标记:先列 RQ,再逐一作答,
  每个 RQ 的答案用一句话加粗总结。这让审稿人"验证闭环"的检查成本为零。
- Discussion 独立成节,与 Results 分开;把"为什么有效/何时失效"写透。

## 4. 表达方式与句式库

### 4.1 摘要(150-250词,7句式)
```
[1] 领域现状:X achieve strong performance on ..., yet their Y remains uncertain.
[2] 现有方法缺陷:Existing ... rely on ..., which fail to ... and often overestimate ...
[3] 提出:We propose NAME (Full-Name), a ... framework that leverages ... to ...
[4] 机制1:By deriving ... from ..., NAME constructs ... and detects ... through ...
[5] 实验:Experiments on six state-of-the-art LLMs show that NAME exposes ...
[6] 发现:We further find that ..., and that ... only partially mitigates ...
[7] 升华:These results suggest that ... should move beyond ... toward ...
    NAME provides a principled and scalable approach for ...
```
高频词:principled, scalable, systematic, unified, collaborative, fine-grained,
substantial, non-trivial, by construction, oracle-free/training-free。

### 4.2 常用句式(从样本中直接提炼)
- 定位:`To the best of our knowledge, this is among the first studies to ...`
- 关键创新:`The key novelty of X lies in grounding ... in ...`
- 机制解释:`This design elevates ... from ... to ..., providing a mechanism
  for ... whose ... are guaranteed by construction.`
- 差异化:`Unlike prior work that ..., our approach ...` /
  `In contrast to ..., we ...`(Related Work 每小节末必备)
- 实验引导:`To answer RQ1, we ...` / `Table 3 reports ... We observe that ...`
- 结论框:`Answer to RQ1: LGMT exposes substantially more reasoning defects
  than reference-based evaluation, with ...%(加粗)`
- 局限:`We acknowledge that ...` / `A potential threat to validity is ...`

### 4.3 用词气质
- 谨慎强于夸张:suggest / indicate / demonstrate 多于 prove(除非真有定理);
  substantially / considerably 多于 dramatically。
- 系统工程词汇密度高:framework, module, component, pipeline, workflow,
  mechanism, paradigm。
- 知识词汇必须高频:knowledge boundary, parametric knowledge, knowledge
  calibration, structured knowledge, knowledge-intensive。
- 数字精确到小数:"a significant 4.7% improvement", "76,298 candidate groups"。

## 5. 图表风格

1. **图1 = 范式对比图**(几乎每篇都有):A. 现有范式1 → B. 现有范式2 →
   C. Ours,用灰字列代表系统名。一张图讲清楚定位。
2. **图2 = 框架总览图**:横向流水线,组件用圆角矩形,阶段用底色分区,
   箭头标注数据形态。方法章各小节编号与图中组件一一对应。
3. **表格风格**:booktabs 三线表;最优值加粗、次优下划线;
   分组行(如 "Systems with Large Models (>15B)")用斜体行分隔;
   Ours 行放最后并命名。
4. **消融表**:w/o 组件名 逐行删减;附 Δ 列。
5. **箱线图/柱状图**做跨模型稳健性;折线图做规模/预算敏感性。
6. 图注要自包含:一句话说明 + 关键读法("higher is better";
   "dashed line marks the contract level α")。
7. 曲线图配色朴素(matplotlib 默认或 colorblind-safe),不玩花哨 3D。

## 6. 审稿人视角的录用清单(复刻前逐项自检)

- [ ] 标题含知识/系统关键词,且能读出"做什么+怎么做":
      "X: A ... Framework for ... via/with ..."
- [ ] 摘要末句有超越本文的领域启示(move beyond ... toward ...)。
- [ ] Highlights 3-5 条,每条 ≤85 字符,动词开头。
- [ ] 引言五段式完整,贡献 4-6 条。
- [ ] Related Work 每小节末有显式差异化句。
- [ ] 方法有总览图 + 形式化问题定义 + 至少1个算法伪代码 + 至少1个
      形式化命题/复杂度分析(KBS 喜欢"有一点理论但不吓人")。
- [ ] 实验列出 RQ(4-6个),覆盖:主结果、消融、敏感性/规模、
      跨模型稳健性、成本/资源、案例或错误分析。
- [ ] 多个 LLM/多数据集(≥3 数据集、≥4 模型是样本中位数)。
- [ ] Discussion 含机理解释 + Limitations(+Threats to Validity 更佳)。
- [ ] 提供代码/数据可用性声明;CRediT 作者贡献;利益冲突声明。
- [ ] 参考文献 60-120 条,近三年占比 >50%,适当引用 KBS 自身论文
      (样本平均引 2-5 篇 KBS 文章——期刊自引是隐性加分)。

## 7. 格式硬性要求(els-cas 模板)

- 模板:`cas-dc`(双栏)或 `cas-sc`(单栏);投稿系统接受两者,
  修改稿常要求单栏行号。用 `\documentclass[a4paper,fleqn]{cas-dc}`。
- frontmatter 必填:`\shorttitle`、`\shortauthors`、`\title`、作者+
  `\affiliation`、`\cormark`/`\cortext`、`\ead`、`\credit`(CRediT)。
- 摘要环境 `\begin{abstract}`;**highlights 环境必填**(3-5条);
  `\begin{keywords}` 用 `\sep` 分隔(4-7个关键词)。
- 参考文献:`\bibliographystyle{cas-model2-names}` + natbib
  `[authoryear]`(KBS 实际发表用数字制,但 CAS 模板默认作者-年份制,
  投稿两者皆可;保持全文一致)。
- 定理环境模板已留接口:`\newtheorem{theorem}{Theorem}` 取消注释即可。
- 图表用 `table*`/`figure*` 跨栏;表格用模板的 `tabular*` + `\tblwidth`。
- 不得修改 cls/sty;所有自定义宏放导言区。

## 8. 从本项目(ContractRAG)到 KBS 论文的映射策略

VLDB 版讲的是"数据库查询优化器"故事;KBS 版必须**换叙事不换实质**:

| 素材 | VLDB 叙事 | KBS 叙事 |
|------|-----------|----------|
| 证据契约 | 声明式查询语义 | **知识充分性规约**(knowledge sufficiency specification) |
| 阶梯/级联 | 物理计划空间 | 渐进式知识获取策略(progressive knowledge acquisition) |
| LTT 认证 | 计划选择的统计保证 | **知识系统可信性认证**(certified reliability) |
| 重写+voucher | 代数重写与风险凭证 | 带风险预算的知识管线简化 |
| e-process 监控 | 运行时验证 | 部署后知识漂移监测与再校准 |
| 多模型族实验 | 供应商泛化 | 跨 LLM 知识源的框架无关性 |
| 基数/访问路径 | 查询优化深度 | 知识源选择(structured vs unstructured) |

写作动作:
1. 标题模式:"Certified/Contract-driven ... Retrieval-Augmented Generation:
   A ... Framework with ... Guarantees"。
2. RQ 化实验:把 VLDB 的 RQ1-RQ9 重组为 KBS 风格 5-6 个 RQ
   (有效性/安全性/消融/跨模型稳健性/漂移适应/开销)。
3. 增加 Discussion 与 Threats to Validity(VLDB 版没有,KBS 必须有)。
4. 理论命题保留 2-3 个即可(证明进附录),KBS 不需要 9 个命题的密度;
   把定理写成"知识保证"而非"优化器保证"。
5. Related Work 前置并分四小节:RAG 与知识增强 LLM;LLM 级联与路由;
   风险控制与保形预测;知识系统的运行时监控。每节末差异化。
